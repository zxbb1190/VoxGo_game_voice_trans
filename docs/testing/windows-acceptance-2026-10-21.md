## 开始测试（约 5 分钟）

1. 正常退出原 0.5.2，避免全局热键和声卡争用；不要卸载或搬动它。验收 ZIP 解压到新文件夹，不能覆盖旧目录。
2. 双击验收根目录的 `Start-Acceptance.cmd`。使用系统现有 PowerShell 策略，不需管理员，不更改防火墙或系统代理。请一直从这个入口启动，避免绕过进程级隔离。
3. 确认窗口是 v0.5.3，识别模型为多语言 `base`（CPU INT8），源语言先选日语、目标中文。在线 Provider 选 OpenAI-compatible，地址保持 `http://127.0.0.1:17853/v1`、模型 `LOCAL_ACCEPTANCE_STUB`、API Key 留空。本轮不要填真实 Key、切到真实接口、开启 Full 或点击下载/更新。
4. 用系统播放器打开 `materials` 中相应 WAV；也可在验收目录运行 `powershell.exe -NoProfile -File .\control\Play-Audio.ps1 -Language ja`（换 `ko` / `ru`）。由 Windows 默认扬声器真实播放，候选采集同一输出设备的 Loopback，不是 benchmark 注入。每条播放后等约 8 秒，再记录结果。
5. 日/韩/俄分别选择、播放；确认目标中文、候选提示、浮窗原文和 `【本地模拟，非真实翻译】` 字样。再做一次 JA→KO→RU→JA 的同进程切换，检查旧语种字幕/任务不会串入。不要改 ASR 阈值、beam、切段或 Prompt。
6. 结束时用浮窗退出按钮正常退出。运行 `powershell.exe -NoProfile -File .\control\Collect-Diagnostics.ps1`，填写 `materials\manual-review-with-smoke.csv`；原始空表为 `manual-review.csv`。本地日志不自动分享，分享前另行检查私人内容和 Key。

显示 `【本地模拟】` 只说明识别、路由和字幕部件链路工作。真实中文译文、API 延迟和翻译正确率均须等本轮之外的新授权，不可据此填“质量通过”。

## 隔离及本地诊断

- 候选设置、授权、模型、日志、缓存均在测试目录。没有复制旧用户 Key、身份、Full outbox 或设置；模型为独立物理副本。手机服务只绑定127.0.0.1:18765，自动更新和模型下载关闭。
- Full 初始与持久授权均为 denied，epoch 为空；程序没有建立 `analytics-remote`。启动器发现非空 Key、外部 OpenAI endpoint、Full 非 denied 或 EXE hash 不符就拒绝启动。
- Basic 与 Full 是两条通道。启动器只对子进程设置 HTTP(S) 拒绝代理，本机服务只监听127.0.0.1，不含任何外部转发实现；HTTPS 在 CONNECT、TLS和正文之前被拒绝。不会修改系统代理、Firewall 或生产配置。
- 已执行负向测试：模拟含63个键的负载被本机 CONNECT 拒绝、正文传出0字节；非空Google Key/外部地址/非denied Full 均启动前拒绝。2个测试方法（含3组配置子案例）通过。测试没有联系生产 Worker。窗口发现直接启动重试前，仅将候选 Basic next_attempt 顺延24小时，保留身份和负载；正式重开仍使用拒绝代理。
- 翻译只用本机模拟及空 Key。运行中也不要填任何 Key 或真实地址；启动前检查不是对用户任意修改运行中配置的沙箱保证。没有新增真实翻译请求，不复用上一轮60次额度。
- 诊断复用原 `app.log` 的识别、语言概率、过滤原因、分段/模式、翻译状态和 `[延迟]`，不开启原始录音保存。`Collect-Diagnostics.ps1` 只按公开材料播放窗口提取，不上传；它不能保证其它本地 app.log 没有同时播放的私人声音转写。原日志不进入干净验收 ZIP 或 Git。
