# v0.5.3 多语言在线候选验证（2026-10-21）

结论：语言框架、在线直达路由、能力限制和自动化回归已完成；**没有任何新增语言获得正式发布质量验收**。公开朗读、PCM 回放和 AI 筛查不能替代真实游戏及双语人工验收。当前已发现战术误译和短切段造成的信息破碎，不建议直接分发为多语言正式版。

## 版本与实现

- 从客户端 `afc33a67` 独立建立 `codex/multilingual-online-053`。原工作区的 `f78f2f6f`、PoC 实验记录及后续文档提交未改动；本分支不包含这些离线 PoC 实现。
- API 保持 `e369e50`，没有业务代码、迁移或协议改动。
- `voxgo/languages.py` 集中定义五种源语言、支持方向与能力检查。支持在线 `en/ja/ko/ru → zh`、`zh → en`；按本轮追加要求补充 `zh → ja`。
- 语言选择和目标过滤使用同一能力表；英中互换保留。无效显式配置保留并提示，不静默变成英语；新增方向展示在线、自配 API Key、质量待验收提示。不切换到其他 Provider。
- 按 [Google v2 官方接口](https://docs.cloud.google.com/translate/docs/reference/rest/v2/translate)，Google 请求显式携带实际 `source/target`；OpenAI-compatible 使用实际语言名称和直接翻译 Prompt。英中原有系统 Prompt 保持逐字不变。可选上下文按语言对隔离，切换清除后晚到结果不能重新污染上下文。
- JA/KO/RU 使用现有多语言 Whisper 及 auto 检测；旧“纯英文”偏好保存但仅 EN→ZH 生效。依据 [Whisper 官方模型能力说明](https://github.com/openai/whisper)，`.en` ID 与原生 `is_multilingual=False` 均拒绝；能力错误透传，不能误报为设备失败。仅扩展语言/脚本识别，不改既有过滤阈值。
- 英中 OPUS 权重、beam、术语、分句和后处理未变。非英中方向在缓存和网络请求之前拦截，本地 Provider 自身也保留原限制。

## 真实在线文本：指定服务商，不中转

仅使用本机既有硅基流动 `tencent/Hunyuan-MT-7B` 配置，不修改配置、不换服务商、不购额度、不上传私人音频或聊天。用户授权最多 60 次真实 API 请求、最多人民币 5 元；每次 HTTP 调用前持久计数，超时也计入，无自动重试。价格依据为 [硅基流动官方价格页](https://www.siliconflow.cn/pricing)，2026-10-21 查询该模型输入/输出均标为免费。费用按此公开费率估算，不能充当账户账单。

96 条新编自编语料固定 dev/holdout 各半；与旧离线调参集合独立。本轮实际文本直译 34 条，未按输出调优或硬编码答案。JA 中另有两条剧情对白；所有参考意义、输出、分组和疑点见 [文本评审证据](evidence/v0.5.3-multilingual-online/text-review.json)。供应商原始返回标签与正式字幕清理后的内容分别保留。翻译设置为 max_tokens=80、temperature=0、timeout=12s、并发1、context_messages=0；仅为测量关闭了英中短语缓存，正式默认缓存保持原样。

## 真实公开语音与正式路径

硬件：i7-13700，16 核 / 24 逻辑处理器，系统可见 RAM 31.75 GiB，Windows。使用既有多语言 base、CPU INT8、beam 1、单 worker/单 ASR 线程、默认 Fast 切段、空 ASR Prompt；无 GPU。模型加载和预热不计入温热链路延迟。

FLEURS 固定版本 `70bb2e84b976b7e960aa89f1c648e09c59f894dd`，CC BY 4.0；9 段公开人类百科朗读及标准转写，实际每语种回放前两段。[逐文件来源、许可、标准转写、SHA 和转换记录](evidence/v0.5.3-multilingual-online/audio-provenance.json)。只核验所使用归档成员，未验证完整远端 tar；不是游戏、剧情角色表演或多人交流样本。

先分别整段 ASR，再按真实时间馈入 PCM，使用正式 `SystemAudioCapture → SpeechPipeline → VoxGoApp → TranslationRuntime → Hunyuan 直译 → GameOverlay`。Qt offscreen 实际部件更新，未接真实声卡/屏幕合成器。精确匹配唯一 PCM 片段起止帧；不能匹配时不推测端到端指标。报告从片段首帧、末帧到部件更新，片段含预滚/静音，不称为标注音素的起止。

offscreen 插件抓图没有绘制文字，因此未将回放 PNG 当作可见字幕证据。另用 Windows 平台插件、系统字体和不展示在屏幕上的隐藏窗口，对日语固定夹具完成视觉检查：[语言选择、候选提示与字幕渲染](evidence/v0.5.3-multilingual-online/ui-preview-native-fonts.png)。这是独立 UI 烟测，不是在线语音的屏幕显示计时；本轮延迟终点始终仅指部件更新回调，真正可见字幕及合成器延迟仍待验收。

第一次回放只用于功能探测，部分时间与全套测试重叠，保留其所有失败记录，**不作为最终性能结果**。最终性能回放在测试、打包结束后单独执行。具体数值、完整请求账本及原始片段将在下表记录。

最终有效字幕 JA 4、KO 5、RU 4 条，均匹配唯一 PCM 边界。P50/P95 按 `(n-1)*p` 线性插值；**n=4/5 的 P95 不具稳定分位推断能力**。首帧与末帧统计分别来自同一条完整链路，不是分阶段 P95 相加。CPU 为进程总CPU秒/墙钟秒×100，100%代表一个逻辑核；不是整机百分比。RSS 包括当前进程依赖与模型，后续语种进程复用，不能声称独立冷启动内存。

整段 CER 为去标点/空白、Unicode字母数字保留、casefold 后的微平均编辑距离：JA 17/69、KO 25/73、RU 2/172；跨语种及短样本不能直接据此推断游戏语义正确率。整段与切段分别报告，不能把整段结果替换流式表现。

丢弃/过滤原始统计：JA filtered=1、dropped=1、transcriptions=5、language gate skipped=1（高置信 en 0.72 的错误英语转写被拦截）；KO filtered=1、transcriptions=5；RU filtered=1、dropped=2、transcriptions=4。切段、合并、过滤是不同单位，不把切段数直接当成功率分母。完整原始记录见 [最终回放](evidence/v0.5.3-multilingual-online/audio-results-final.json) 与 [统计计算](evidence/v0.5.3-multilingual-online/performance-summary.json)。

调用总量 **60 次**：自编文本34、首次链路13、最终链路13；均获得非空响应，无HTTP失败/超时，原配置字节未变。已到上限并停止，无额外重试。按当日官方免费费率估算0元，未核对账户账单。[调用账本](evidence/v0.5.3-multilingual-online/budget.json) 不含密钥、安装标识或私人内容。

已经确认的 ASR/链路风险：

- 日语整段把 `参列者` 识别为 `3列車`，`葬儀` 识别为 `装備`；短切段后还出现把后续片段单独译成列车汽笛或装备准备的内容。
- 韩语整段第一句发生尾部遗漏；切段中专名被拆碎，`원소`（元素）误识别为其他词，中文随错误转写变成“价格”等内容。
- 俄语整段相对接近标准转写，但切段将“包括心理学”等从句拆散，在线模型会重释残片。不能用整段 ASR 结果替代正式切段质量。
- 未为这些样本调 ASR、beam、Prompt、术语或 OPUS。失败样本均保留；不只统计成功快片段而隐藏丢弃数。
- 本轮开发 venv 中 Qt 先于 CT2 导入时曾在原生模型初始化触发 access violation。评估脚本改为正式入口的初始化顺序，并排除正式包本来不包含的 Torch/Transformers 后继续；故障阶段没有发出额外在线请求。没有因此修改正式模型/依赖，仍需实际发行包和设备验收。

## 发布判断与缺口

JA/KO/RU 与补充 ZH→JA 均为**技术候选、未通过质量发布验收**。英文/中文方向保留原行为，本轮两条在线 EN→ZH 小样也发现既有语义风险，不将其包装为新功能通过率。

仍需：有许可且有标准转写的日语真实角色/剧情对白、韩/俄真实多人开黑录音；独立 holdout 的双语人工复核；正式数值门槛；实际声卡、屏幕显示、真实游戏 FPS / 1% low、长时间排队及弱网测试；目标低配 Windows 真机。此次 i7 运行不是低配实测，也不能推导游戏性能影响。

Google 真实调用及其他 Provider/模型独立验收仍未完成。不得因供应商宣称支持、单元测试或 AI 筛查就宣传某语种达到正式实时游戏字幕质量。

本轮不执行 D1 migration、Worker deploy、push、tag、GitHub Release 或客户端分发。生产顺序仍为备份 D1 → 0006 → 兼容 Worker → 受控事件验证 → 完成所有发布门槛后再分发；不得用本候选包绕过语言质量验收。
