# v0.6.0 模型切换下载/加载提示修复

基线 `d0068c24`，分支 `codex/release-0.6.0`。本轮只修复模型准备状态的呈现，不调整韩语及其他语种的模型选择、识别/切段/过滤参数、翻译 Prompt、英中 OPUS 或 63 字段 Telemetry。

## 确认的提示缺陷

原 `VoxGoApp._notify_model_download_progress` 将下载提示放在普通字幕历史中，并用 `_model_download_notice_started` 永久记住“已经创建”。历史因滚动、淡出或清空而删除该条目后，下一次换模型只调用 `update_translation` 更新旧 ID。`GameOverlay._update_translation` 找不到条目就返回，后续下载实际上有回调，界面却没有提示。

修前使用真实 Qt 浮窗、最多 3 条字幕复现：初次状态条目数为 1，插入 3 条字幕后再发送 small 模型检查事件，状态条目数为 0。没有发起下载或翻译请求。

用户 2026-10-29 的 Lite 日志还确认：韩语切均衡后 small 首次下载/加载造成约 28 秒等待。下载后另有语种不匹配、ASR 后过滤以及切换后的旧结果作废；用户无法提供原音，本次不将这些问题归结为下载，也不修改相关规则。

## 改动

- `voxgo/app.py::_queue_recognizer_config`：选用的模型发生变化时立即显示等待切换状态。保留原先“下一段音频到来时检查/加载”的时机，不主动增加下载。
- `voxgo/app.py::_notify_model_download_progress`、`voxgo/ui/overlay_window.py::set_model_preparation_progress`：使用专用 Qt 信号传递原始进度到 GUI 线程；不再借用字幕历史或普通译文更新接口。
- `voxgo/ui/model_preparation_status.py::ModelPreparationStatus`：独立状态区不参与历史滚动、清空及字幕复制。500ms 刷新计时；真正加载成功后显示“已就绪”6秒，失败提示保留。退出停止计时并拒绝排队的晚到事件；再次切换时，旧模型完成不得误报新模型已就绪。
- `voxgo/asr/whisper_engine.py::SpeechRecognizer.initialize`：区分模型缓存完成、引擎加载、真正可用和加载失败。提示回调异常不能让已加载模型变成加载失败。未修改原生模型加载参数、回退条件或转录参数。
- `voxgo/asr/model_download_notice.py::ModelDownloadNoticeFormatter`：显示已下载大小、百分比、已用时间、速度和有依据的预计剩余时间。新模型/重试重置计数；缓存已有字节不参与本次速度计算。至少有2秒有效增量、已知总大小且最近3秒有新数据时才给出剩余估计，停滞时撤下过期估计。加载阶段不伪造倒计时。
- Hugging Face 的单文件进度明确标记为文件进度，不冒充整个模型的百分比或总剩余时间；单文件完成也不宣称整个缓存就绪。`progress_scope` 只是可选的内部 UI 事件元数据，不属于持久设置或 Telemetry。
- 所有新增提示包含简中、英文、日文、韩文、俄文；没有新增运行依赖、字体资源或安装包外部服务。
