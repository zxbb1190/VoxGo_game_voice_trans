# v0.6.0 R2：全语种无识别/字幕的启动修复

分支 `codex/multilingual-online-053`，缺陷版本为R1（运行代码`0a23fc67`），修复提交`5615b599`。版本仍为未发布的0.6.0；原发行包已新增WITHDRAWN标记，ZIP和历史证据不覆盖。

## 已确认根因

`voxgo/app.py::VoxGoApp._finish_backend_startup`构造启动方向提示时调用了未导入的`language_label`。它发生在`_running=True`和识别worker启动之后、音频捕获与100ms消费定时器创建之前，导致半启动状态。后来切换设置能够单独重启采集生产者，但没有定时器消费PCM，所以只有原始队列持续溢出，没有语音提交识别，翻译自然没有输入。

用户日志显示两次模型加载完成、两次worker启动、**零次后端启动完成、零次语言门控通过、53次原始队列满**。实际日志切换过en/zh/ja/ko，不能把用户日志虚构成RU实测；该未定义名称在所有方向都会触发，已另行复现并覆盖全部方向。只归档日志SHA和阶段计数，保留用户原日志，不归档私人设置、Key或可能的语音正文。

直接调用旧启动函数准确复现`NameError: name 'language_label' is not defined`，worker已启动而capture/timer均未启动。这是应用启动代码缺陷，不是模型未下载、CPU策略或已确认的Provider故障。前次`--help`仅验证导入，漏掉了这个后端初始化阶段，不能当作完整启动通过。

## 最小修改

- `voxgo/app.py`显式导入`language_label`。
- `_finish_backend_startup`先建立音频捕获和消费定时器，再输出可选横幅/启动提示；提示异常记录应用日志，不能阻断已启动的识别链路。
- 新增`tests/test_backend_startup.py`：5种界面语言×20方向调用真实启动收尾函数；真实Qt timer触发音频consumer；提示/控制台异常不能停止音频处理。

不改ASR数值、模型、切段、过滤、Prompt、翻译规则、63字段协议或日/韩兼容、俄Fast候选的既定组合。
