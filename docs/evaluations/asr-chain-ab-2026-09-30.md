# VoxGo 实时 ASR 链路失败回放与有界 A/B（2026-09-30）

## 范围与状态

本轮只诊断 `whole` 正确或更好、`capture_cut` / `full_pipeline` 变差的自然英语。产品的捕获参数、`SpeechPipeline`、模型、Prompt、Fast/Balanced 预设、翻译及 UI **均未改动**；A/B 覆盖值只作用于 Benchmark 实例。没有发布版本，也没有真实玩家语音验证。

沿用[三路径基线](asr-three-path-2026-09-30.md)的真人 LibriSpeech 朗读和 AMI 会议语音，以及原来的 clean / 20 dB / 0 dB 本地合成噪声。两种语料分别报告，不将失败集的 WER 当作总体 WER。每个语料 × preset × 噪声档选一条突出切段退化、一条突出 Pipeline 额外退化，共 **24 条定向失败样本**；另从原报告确定性选出互不重叠的 **24 条独立对照**。配置固定为 `base.en/fast/Prompt off`、`small.en/balanced/Prompt off`，CPU int8；逐个独占进程按真实时间回放。失败集三路径 72 条、对照集三路径 72 条，均零失败。原始基线报告原样保留。

诊断记录每段原始音频路径、PCM 精确匹配出的源音频边界、时长、RMS、峰值/门限、逐块 VAD/能量/活动、切段原因、逐段 Whisper 文本和置信字段，以及候选、等待、队列、过滤、字幕输出与时间。失败集最初回放与显式队列追踪复跑均有 **109/109 段**能与源 PCM 精确匹配；所有记录的活动块均落在已输出片段内。这排除了该集上可见的“活跃块整段没交给切段器”，**不能排除 VAD 把真实弱语音判为不活跃**。显式队列追踪复跑 72 条路径、零失败，记录到带音频哈希的 **85 次有效入队、85 次工作线程出队**；其分类与原回放一致。个别输出、drop 数以及绝对推理时间在两次回放间有波动，故 A/B 只与同批原回放基线配对，显式队列追踪只用于核对事件路径。详细逐条审阅和原始 JSON 保存在本机忽略目录 `diagnostics/asr-chain-ab/baseline/` 与 `baseline_queue_trace/`。

## 哪一层丢了什么

下表是**定向失败集的关联分类**：每个正向增量只归入一个最明显的可观测现象，错词数是相邻路径的正向规范化错词增量，**不是严格的逐词因果归因**。同一音频可以同时贡献切段和 Pipeline 两层。

| 路径增量 | 关联现象 | 正向退化样本 | 额外错词 |
| --- | --- | ---: | ---: |
| whole → capture_cut | 达到最长时长强制切段 | 12/19（63%） | 88/123（72%） |
| whole → capture_cut | 多个短碎片 | 6/19（32%） | 30/123（24%） |
| whole → capture_cut | 切段上下文或 Whisper 逐段解码 | 1/19（5%） | 5/123（4%） |
| capture_cut → full_pipeline | 弱候选 ASR 预算丢弃 | 12/14（86%） | 38/42（90%） |
| capture_cut → full_pipeline | 识别后文本过滤 | 2/14（14%） | 4/42（10%） |

实际日志出现 **30 次最长时长切段、22 次弱候选 ASR 预算丢弃**；没有观察到队列容量满、busy-stale 丢弃或候选成功合并。故未对“增加队列容量/延长 busy-stale”做无事件依据的实验。原始日志可见个别 pre-ASR 丢弃与更多 post-ASR 过滤，但只有上表两条过滤关联到本轮正向 Pipeline 退化。**没有确认句首/句尾 PCM 被直接剪掉，也没有确认错误合并**；这并不证明这些情况在其他游戏音频里不存在。0 dB 样本可出现噪声使 VAD 几乎持续活跃，推动强制时长切段，但现有样本不足以给“噪声 VAD 误判”独立量化贡献。

Fast 的主要问题是 **2.5 秒上限把长句连续强切成缺少上下文的片段**，并产生随后容易被预算抛弃的短弱候选。Balanced 上限是 4 秒，切段损失仍存在；AMI 会话中的短片段受候选预算与输出过滤影响，Pipeline 有时进一步漏词。整段 `whole` 在 0 dB 本身也会明显恶化，这部分与实时链路增量不同，不能靠队列参数补回。

## 同批失败样本的单变量 A/B

每个实验均回放相同 24 条定向样本；下列“错词/漏词”是四组样本**计数之和**，只用于配对比较，不能合并两种语料算总体 WER。`drop` 为 Pipeline 的 dropped_speech 事件数；基线为 **268 错词 / 136 漏词 / 22 drop**。本表平均 ASR 时间是每条音频所有推理调用之和，墙钟包括实时播放和排空队列，不是字幕可见延迟；进程 CPU 时间是粗略资源代理。

| 只改一个变量 | 错词 | 漏词 | drop | ASR 调用数 | 平均 ASR / 墙钟 / CPU，基线→A/B | 判断 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| Fast 2.5→3.0s；Balanced 4.0→4.5s | 268→233 | 136→114 | 22→27 | 85→76 | 3.90→3.58 / 10.88→10.75 / 6.29→5.83s | 有收益，但见独立对照 |
| 弱候选冷却 0.35→0s | 268→245 | 136→103 | 22→0 | 85→105 | 3.90→4.85 / 10.88→11.09 / 6.29→7.62s | 漏词减少，推理/CPU 成本增大 |
| 候选等待 +0.15s | 268→265 | 136→133 | 22→21 | 85→86 | 3.90→3.99 / 10.88→10.90 / 6.29→6.34s | 收益太小 |
| 让 ≥0.4s 有声弱候选免预算丢弃 | 268→248 | 136→106 | 22→8 | 85→100 | 3.90→6.73 / 10.88→11.83 / 6.29→10.20s | 成本过高 |
| 低置信过滤里放行少数高置信英语短句 | 268→262 | 136→128 | 22→22 | 85→85 | 3.90→3.92 / 10.88→10.89 / 6.29→6.22s | 放出一条错误文本，不能上线 |
| 短候选等待合并资格 0.8→1.0s | 268→270 | 136→135 | 22→22 | 85→85 | 3.90→4.11 / 10.88→10.90 / 6.29→6.45s | 没有稳定改善 |

放宽过滤救回了 `Empire.`、`O Love!`、`or were they?`，但也放出了相对标准答案错误的 `So far.`。保留现有 runaway repetition guard；以上所有失败集 A/B 的**最终失控重复均为 0**，但这不足以证明放宽过滤在更大语料中安全。合并资格 A/B 未产生可支持收益的实际合并。两种减少预算丢弃的方案都以更高推理量换回漏词，未满足“不明显增加 CPU/延迟”的目标。

### 切段上限的独立对照

这是唯一另跑 24 条**未用于挑选失败的**独立对照的 A/B。各行 6 条，均为规范化 WER；切段上限变化不影响 `whole`。

| 语料 / 模式 | 定向失败集 full_pipeline | 独立对照 capture_cut | 独立对照 full_pipeline | 独立对照漏词率 full_pipeline | 对照 drop |
| --- | ---: | ---: | ---: | ---: | ---: |
| LibriSpeech / Fast | 40.23→36.78% | 21.59→20.45% | **22.73→22.73%** | 6.82→7.95% | 1→0 |
| LibriSpeech / Balanced | 41.84→27.66% | 14.56→7.77% | **13.59→7.77%** | 5.83→1.94% | 2→0 |
| AMI / Fast | 79.00→73.00% | 40.54→41.89% | **44.59→45.95%** | 31.08→31.08% | 1→2 |
| AMI / Balanced | 55.56→52.78% | 25.26→25.26% | **28.42→28.42%** | 24.21→24.21% | 2→2 |

独立对照显示延长切段对 LibriSpeech Balanced 有较大收益，但 Fast 无一致收益，AMI Fast 甚至恶化。对照集所有 `full_pipeline` 的平均 ASR 调用和回放墙钟分别为 **3.10→2.76s**、**7.49→7.35s**；未见明显延迟代价，但每组只有 6 条。原基线与显式队列追踪复跑中相同 `whole` 的绝对推理时间也明显变化，说明机器状态漂移；表内耗时仅提供成本量级，不能将小幅秒数差精确归因于参数。所有对照最终失控重复为 0。需要更大、独立且含真实游戏音频的验证，才能考虑改正式切段上限。

## 结论与下一步

当前证据把实时链路额外损失定位到两处：**强制切段/短碎片先损坏上下文，弱候选推理预算与个别输出过滤随后增加漏词**。Fast 的首要瓶颈在切段，Balanced 的主要可观察 Pipeline 附加损失在弱候选丢弃；0 dB 的整段模型退化仍然独立存在。延长切段上限是唯一值得继续验证的方向，但独立对照只支持 LibriSpeech Balanced，不支持一次改动覆盖 Fast/Balanced。其他候选/过滤 A/B 的收益、CPU 或误报代价不满足进入正式代码的条件。**本轮保持正式产品参数现状**，保留失败集、对照集和诊断工具供下一次更大、独立的自然语音及经同意的玩家录音验证；不据此提出发布或模型策略变更。
